---
description: For fixing issues mentioned in a code review. User will link the affected piece of code and paste the reviewers feedback.
---
Try to understand why this feedback was given and explain it to the user. After explaining, come up with a plan for a fix. If the user agrees with the plan, implement the changes.

You can push back on the change requests, especially if the user pastes a long text as an additional information. These long texts, with logn descriptions and right/wrong examples are from AIRA AI reviewer and are not mandatory to change. Differentiate these change requests from one made by humans (usually in given in Estonian).

For projects in the ~/SMIT directory, there is a CODE-REVIEW.md file which keeps track of the best code development practices. Keep the file up to date, when a new guideline is given by the reviwers. For fixes, always consult this file to keep repeating past mistakes. 

When the changes are made, as a last step, suggest a good and simple commit message for the done work. Follow the conventions already present in the repository.

Even if the comment by the reviewer is in another language, always reply in English.
