description: Explain the file, line, method or term name like I'm 5.
---

- Quite often, the reason for asking for an explanation is the fact that the user is unfamiliar with the language, framework, library, term or architecture. 
- If skill call contains no arguments, explain the last response.
- If a file is cited, explain the reason for the file's existance, what it does and why it is needed. Same with lines.
- If an argument has been supplied, use this as a guide for what needs to be explained. 
- Keep the answers short and on-point. We need to aovid situations where a simple questions produces a "wall of text".
- After the explaination, offer to elaborate on the same topic or go in-depth with a related topic.
